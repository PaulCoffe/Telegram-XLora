# План исправления падения сборки на GitHub

## Проблема
Сборка на GitHub Actions падает повторно после интеграции Mesh функционала. Вероятная причина: отсутствие сборки нативных зависимостей (FFmpeg, VPX, BoringSSL) в CI пайплайне, что приводит к ошибкам линковки.

## Анализ
- Workflow `.github/workflows/build-apk.yml` настраивает JDK, NDK и инструменты сборки, но не выполняет скрипты сборки нативных библиотек.
- Согласно `BUILDING.md`, перед сборкой APK необходимо выполнить:
  - `./build_libvpx_clang.sh`
  - `./build_ffmpeg_clang.sh`
  - `./patch_ffmpeg.sh`
  - `./patch_boringssl.sh`
  - `./build_boringssl.sh`
- Это критично для проекта с нативным кодом (JNI).

## План действий
1. **Обновить workflow**: Добавить шаг сборки нативных зависимостей перед сборкой APK.
2. **Проверить переменные окружения**: Убедиться, что NDK, NINJA_PATH, ANDROID_SDK и ANDROID_HOME правильно установлены.
3. **Добавить CMake**: Workflow устанавливает CMake через sdkmanager, но убедиться в версии.
4. **Тестировать локально**: Перед коммитом протестировать сборку нативных libs локально.
5. **Обновить документацию**: Обновить ARCHITECTURE.md с деталями CI процесса.
6. **Мониторить сборку**: После фикса проверить успешность на GitHub Actions.

## Риски
- Сборка нативных libs может занять значительное время, увеличить длительность CI.
- Возможны конфликты версий NDK или инструментов.
- Требуется достаточное дисковое пространство на runner'е.
